# Oword 설계

Oword는 Opptx의 네 층 구조를 그대로 따릅니다. Opptx는 HOP(HWP 편집기)을 REA로 분석해서 얻은 구조를 PPTX에 옮긴 것이고, Oword는 같은 구조를 DOCX(WordprocessingML)에 옮겼습니다.

| 층 | HOP | Opptx | Oword |
|---|---|---|---|
| 문서 엔진 | rhwp (Rust→WASM) | `document.ts` (슬라이드/도형 명령) | `document.ts`, `model.ts`, `styles.ts`, `numbering.ts` |
| 렌더러 | `renderPageToCanvas` | `render.ts` (슬라이드 → DOM/SVG) | `render.ts` (본문 → 편집 가능한 HTML) + `editor.ts`의 쪽 배치 |
| 명령 기반 UI | `data-cmd="category:action"` | `src/ui/commands.ts` | 같은 파일을 그대로 사용 |
| 데스크톱 셸 | Tauri, staged save | `src-tauri/` | 같은 셸 (필터와 이름만 DOCX로) |

## 원칙: XML이 단일 원본

- 모든 XML 파트는 열 때 DOM으로 파싱해 두고, 명령은 그 DOM을 고칩니다. 렌더러는 읽기만 합니다.
- 바꾼 문단만 다시 만들고, 나머지 문단 요소는 그대로 옮겨 놓기 때문에 필드, 책갈피, 메모 범위, 변경 내용 추적, 알 수 없는 확장 요소가 저장 후에도 남습니다.
- 속성 요소(`w:rPr`, `w:pPr`, `w:sectPr`)는 스키마 순서대로 넣습니다(`xml.ts`의 `*_ORDER`). Word는 순서가 틀린 파일을 "읽을 수 없는 내용"으로 처리합니다.
- 되돌리기는 트랜잭션 전후의 파트 스냅샷(직렬화한 XML)을 저장하는 방식입니다(Opptx와 같음).

## 문단 내용 모델 (`model.ts`)

`w:p`는 항목(item) 목록으로 읽습니다: 글자, 탭, 줄 바꿈, 쪽 나누기, 인라인 개체(그림·기호·각주 참조 등), 필드, 숨은 표지(책갈피 등).
글자 항목의 길이는 글자 수, 개체·탭·줄 바꿈은 1, 숨은 표지는 0입니다. 이 길이가 **모델 위치** `{pi, off}`(문단 번호, 문단 안 위치)를 정의합니다.

서식 명령은 범위의 경계에서 런을 나누고(`explode`, `splitAt`), 사이의 런을 고친 뒤, 속성이 같은 이웃 런을 합칩니다(`mergeRuns`).

## 편집 (`edit.ts`, `editor.ts`)

- 본문 전체가 하나의 `contenteditable`입니다. 글자 입력과 지우기는 브라우저가 처리하고(한글 IME 그대로), 입력이 멈추면 DOM을 모델에 반영합니다(`commitDom`).
- 렌더링할 때 문단, 런 속성, 인라인 개체, 하이퍼링크를 레지스트리에 등록합니다. 반영할 때는 렌더링 당시와 HTML이 같은 문단은 원래 XML을 그대로 쓰고, 바뀐 문단만 등록된 런 속성과 개체로 다시 만듭니다.
- Enter, Tab, 서식, 표, 그림 같은 구조 명령은 엔진이 처리합니다. 먼저 입력을 반영하고, 모델 위치로 명령을 실행한 다음, 바뀐 문단만 다시 그리고 선택 영역을 모델 위치로 복원합니다.
- 커서만 있을 때 서식을 바꾸면 Word처럼 단어 전체에 적용하고, 단어 밖이면 "다음 입력" 서식으로 빈 런(폭 없는 공백)을 커서 위치에 넣습니다.

## 쪽 배치

블록(문단, 표)마다 위치와 높이를 재고, 쪽 아래 여백을 넘는 블록을 다음 쪽 위로 밀어냅니다(`--push` 여백). 강제 쪽 나누기, 문단 앞 쪽 나누기, 구역 나누기, "다음 문단과 함께"를 처리합니다.
쪽 틀(흰 종이, 머리글/바닥글)은 본문 뒤의 별도 층에 그립니다. 인쇄할 때는 쪽 사이 간격을 0으로 다시 배치하고, 계산한 위치를 써서 쪽마다 블록을 복사합니다.
